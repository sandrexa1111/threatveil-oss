# Roadmap after category-foundation implementation

> Historical commercial roadmap (September 2026), kept for context. The current open-source roadmap is [ROADMAP.md](../ROADMAP.md).

This is an evidence-gated sequence, not a claim that hosted customer outcomes are scheduled or complete. Autonomous Release Integrity remains the entry wedge; Autonomous Change Assurance is the maintained system/state/authority relationship.

| Stage | Current status | Exit evidence |
|---|---|---|
| Canonical and commercial foundation | Implemented and locally accepted | Exact scope, useful task, source-change/finality negatives, signed records, quotas/lifecycle, browser and existing-kernel regressions |
| Private GCP readiness configuration | Prepared, configuration incomplete | Reviewed immutable images, identity/key custody, least privilege, budgets, alerts, rollback and recovery profile; all preflight configuration checks |
| Private GCP operation | Requires authorized deployment and live acceptance | Managed login, two tenants, actual broker/worker/relay, cloud source, exact Check, restore, retention and rollback evidence |
| Stripe TEST lifecycle | Implementation prepared; external acceptance pending | Configured test keys/prices, signed actual test events, signup/upgrade/downgrade/failure/replay, paid=false |
| Prepared design partner | Requires customer scope/access | Independent business observer, approved positive/adverse fixtures, consequential non-code change, accepted external decision and acknowledgement |
| Bottom-up adoption and repeat use | Unvalidated commercial hypothesis | Real conversion, repeated changes, false-warning adjudication, support/verification cost and second-system adoption |
| Advanced enterprise controls | Contract/capability architecture only where documented | Authenticated operator provisioning, accepted SSO/private connectivity/control adapters and contracted support operations |

Near-term engineering follows observed acceptance gaps: hosted operator contract provisioning; qualified deployment-state and external acknowledgement adapters; measured ledger projection/query cost; explicit source-gap reconciliation; retention/erasure operations; signing trust distribution/rotation. Do not turn these into positive production assurances before acceptance.

Do not expand into generic IAM, observability, CI/CD, autonomous remediation, dozens of shallow connectors, physical control or payment processing. Future component/protocol/provider changes should enter the same typed contract, qualification and falsification process.
